# Концепция и план развития

## Модель

**Условие (Term)** — атомарная коммерческая договорённость, «токен»:

| Поле | Смысл |
|---|---|
| `source` | `contract` — из договора/допсоглашения; `promo` — акция |
| `effect` | `percent_off`, `amount_off` (₽/шт.), `fixed_price` (₽/шт.) |
| `base` | для акций: от прайса (`list`, по умолчанию) или от договорной цены (`contract`) |
| `scope` | товары: `all`, `skus`, `categories`, `excludeSkus` |
| `audience` | клиенты: `all`, `customerIds`, `segments` |
| `validFrom` / `validTo` | срок действия, включительно; без `validTo` — бессрочно |
| `minQty` | порог количества в строке |
| `priority` | ручное разрешение конфликтов (больше — важнее) |
| `document` | документ-основание в ЭДО (можно задать на весь файл) |
| `minMargin` / `maxQtyPerOrder` / `budget` | ограничители акции: мин. маржа, лимит штук в заказе, бюджет (см. ниже) |
| `mechanic` | механика акции: ссылка на пресет из справочника (см. «Пресеты механик») |

## Правила расчёта строки

1. Прайсовая цена.
2. Договорная цена: одно условие договора — по приоритету, затем по точности (SKU > категория > всё), затем самое позднее.
3. Каждая действующая акция даёт свою цену (от прайса или от договорной).
4. Применяется минимальная цена. При равенстве — больший приоритет, затем договор.

Следствия: акции не «накручиваются» друг на друга бесконтрольно; окончание акции = возврат к договору без ручных действий; каждое решение объяснимо.

## Ограничители акций

Акция может задать ограничители — страховку от «акции в убыток»:

| Поле | Смысл | Поведение |
|---|---|---|
| `minMargin` | минимальная маржа, % от себестоимости | **блокирующее**: цена акции ниже порога (себестоимость × (1 + маржа)) не применяется, причина — в объяснении строки |
| `maxQtyPerOrder` | лимит штук в одном заказе | **блокирующее**: строка сверх лимита не получает акцию, показывается подсказка «доступно до N шт.» |
| `budget` | бюджет акции, руб. | **учётное**: по корзине считается расход каждой акции (скидка × количество); превышение — предупреждение в `priceCart().warnings`, акция не блокируется |

Себестоимость (`cost`) приходит из учётной системы в карточке товара; соответствие полей 1С УТ и движка описано в `seed/1c-mapping.json` (файл-контракт: правится при смене структуры 1С, а не кода). Валидатор проверяет и сами ограничители (диапазоны значений), и согласованность (акция, которая сама нарушает свой порог маржи, «никогда не применится» — предупреждение).

Реальное потребление бюджета в момент заказов требует сервера и журнала продаж — это этап 1; в песочнице бюджет считается по корзине.

## Карточка товара

`Product` — граница между учётной системой и сайтом: ключевые коммерческие поля (`sku`, `listPrice`, `cost`, `category`) и описательная часть для витрины и CRM (`description`, `attributes`, `unit`). Маппинг полей 1С УТ — в `seed/1c-mapping.json`: блок `required` обязателен (загрузчик падает, если поля нет), блок `optional` — по возможности.

## Масштабирование

Выборка условий для товара идёт через инвертированный индекс (`buildTermIndex`): весь ассортимент + по SKU + по категории, минус исключения — O(условий на товар) вместо перебора всех условий. На синтетике разницы не видно, на каталоге в десятки тысяч SKU — принципиально. Индекс строит загрузчик; без него ядро работает линейно (fallback).

## Запуск заказа

Корзина может храниться сколько угодно — цены в ней «живые». В момент запуска движок проверяет условия оплаты клиента и создаёт **неизменяемый снимок** с ценами, применёнными условиями и документами-основаниями.

## Пресеты механик акций

**Механика** — именованный рецепт акции: тип эффекта (скидка %, скидка ₽/шт., фиксированная цена) и база расчёта (от прайса или поверх договора). Комбинаций немного, поэтому механики — закрытый справочник (`seed/presets.json`), а не свободная форма: акция наследует настройки своей механики через поле `mechanic`.

Статусы механики (`mechanicStatus`):

| Статус | Смысл |
|---|---|
| активна | доступна в конструкторе акций, на ней пока нет действующих |
| используется | на ней созданы запланированные или действующие акции |
| в архиве | не предлагается для новых акций; существующие акции продолжают работать |

Страница `web/presets.html`: карточки механик со схемой «база → эффект», статусами и списком стоящих на них акций; конструктор новой механики — модальное окно (комбинаций мало, отдельная страница не нужна). В песочнице справочник механик статичен (git), окно проверяет рецепт и выдаёт готовый JSON-фрагмент для `seed/presets.json`; в боевой системе создание механики — запись в БД (этап 1).

## Управление акциями (админка)

Админка акций (`web/admin.html`) — список акций со статусами, без изменения условий:

- **Статусы**: `включена` (срок действует, не отключена), `запланирована` (начнётся позже), `выключена` (принудительно отключена вручную), `архив` (срок проведения прошёл). Статус по срокам даёт `promoPhase` (`запланирована / действует / архив`), ручное отключение — слой состояния поверх: оно перекрывает плановый статус, архив — терминальный.
- **Диапазон дат списка** — настраивается (по умолчанию ближайшие 12 месяцев), история завершившихся акций доступна сдвигом диапазона. В список попадают акции, чей срок пересекается с диапазоном.
- **Сортировка** — по названию акции и по дате начала, в обе стороны.
- **Ручное отключение / повторное включение** — не меняет условия акции: движок получает `catalog.disabledPromos` (набор id) и исключает акцию из расчёта с объяснением в строке («акция отключена администратором»). В витрине пересчёт — сразу.
- **Кнопки перехода**: «Добавить акцию» → страница настройки акции, «Пресеты механик» → конструктор параметров механик (обе страницы пока каркасные — интерфейс детально прорабатывается отдельно).

Слой состояния в песочнице хранится в `localStorage` браузера (ключ `gifts.promo-off`) и разделяется страницами одного origin; в боевой системе это таблица в БД (этап 1). Условия акции при любом переключении не меняются — меняется только их участие в расчёте.

## Вопросы для проработки (открытые)

- Совмещение нескольких акций в одной строке (сейчас — только лучшая, плюс «акция поверх договора»).
- Акции на корзину целиком (порог суммы заказа, подарок, набор).
- Согласование: черновик → согласовано → опубликовано (сейчас — коммит в git).
- Персональные предложения в ЛК и конструктор КП на тех же условиях.
