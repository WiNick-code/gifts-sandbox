# gifts-sandbox

Песочница для проработки **системы управления акциями и коммерческими условиями** B2B-сайта сувенирной продукции. Начинается с движка расчёта цены, по мере развития — прототип витрины, корзины и личного кабинета.

> ⚠️ Репозиторий публичный. Только **синтетические данные**: никаких реальных клиентов, цен, договоров и выгрузок из CRM.

## Что уже умеет движок

- **Условия как «токены»**: каждая договорённость — отдельное условие с охватом (SKU / категория / всё), аудиторией (клиент / сегмент / все), сроком действия, порогом количества и ссылкой на документ ЭДО.
- **Договорная цена клиента** складывается из условий договора и допсоглашений: более точное (SKU > категория > всё) и более позднее перекрывает общее.
- **Акции** считаются от прайса или от договорной цены (`"base": "contract"` — акция поверх договора). Клиент получает лучшую цену.
- **Автоматический возврат к договорным условиям**: закончилась акция — цена сама становится договорной.
- **У каждой строки корзины — свои условия**, с объяснением: что применено, что отклонено и почему, чего не хватило («доступно от 500 шт.»).
- **Запуск заказа**: проверка условий оплаты (предоплата / отсрочка / отсрочка с лимитом) и фиксация цен в неизменяемом снимке.
- **Валидатор правил**: дубли, даты, диапазоны скидок, несуществующие товары и клиенты, неоднозначные условия договора.

## Как запустить

Нужен Node.js 22.18+ (TypeScript запускается напрямую, без сборки). Зависимостей для запуска нет.

```bash
npm test                                   # тесты сценариев
npm run validate                           # проверка правил
node scripts/price.ts C-001 2026-12-01 NY-01:10 TH-01:2 PEN-02:100
```

Проверка типов: `npm install`, затем `npm run typecheck`.

## Демо-страница

`npm run build` собирает `dist/index.html` — один самодостаточный файл: ядро движка и правила встроены внутрь, сервер не нужен. Выберите клиента и дату, соберите корзину — страница покажет цену каждой строки, объяснение, подсказки по порогам, условия на дату, а при запуске заказа — зафиксированные цены.

Публикация: при каждом пуше в `main` GitHub Actions прогоняет тесты, проверку правил и выкладывает страницу на GitHub Pages (Settings → Pages → Source: **GitHub Actions**). Тот же `dist/index.html` подходит для GitVerse Pages.

Шаблон страницы — `web/index.html`, сборка — `scripts/build-web.ts`. Тест `engine/test/build.test.ts` проверяет, что собранное для браузера ядро считает так же, как исходное.

Без установки чего-либо — откройте репозиторий в облачной среде (GitHub Codespaces или GigaIDE Cloud на GitVerse): Node там уже есть.

## Структура

```
engine/src/   ядро: типы, сопоставление условий, расчёт цены, запуск заказа, валидатор
engine/test/  тесты — по сути, исполняемая спецификация правил
rules/        условия: contracts/<клиент>/<дата>_<документ>.json, promos/<период>.json
seed/         синтетический каталог и клиенты
scripts/      командная строка: расчёт корзины, проверка правил, сборка демо
web/          шаблон демо-страницы
docs/         концепция и план развития
```

## Как добавить условие

Создайте JSON-файл в `rules/` (по одному файлу на документ: договор, допсоглашение, приказ об акции) и запустите `npm run validate`. История изменений условий — это история git: кто, когда и по какому документу изменил коммерческие условия.

Подробнее — [docs/concept.md](docs/concept.md).
